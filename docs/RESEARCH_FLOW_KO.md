# 연구 흐름과 의사결정 지도

이 문서는 “어떤 분석을 했는가”보다 “왜 그 순서로 했고, 각 결과가 다음 판단을 어떻게 바꿨는가”에 초점을 둔다.

## 단계별 연결

| 단계 | 입력 | 핵심 질문 | 판단 | 다음 단계에 준 영향 |
|---|---|---|---|---|
| 1. 데이터 감사 | AI4I 2020 원자료 | 라벨과 분포를 믿을 수 있는가 | 고장 3.39%, 정합성 예외 27건 | 불균형 지표와 보수적 해석 채택 |
| 2. 순차 분할 | 관측 순서 | 정보누출 없이 평가할 수 있는가 | 70/15/15 고정 | 검증은 선택, 테스트는 최종평가로 역할 분리 |
| 3. EDA·특성 설계 | 센서·운전 변수 | 물리적으로 의미 있는 조합은 무엇인가 | 온도차, 기계동력 생성 | 비선형 모델 입력과 최적화 제약에 사용 |
| 4. SQC | 학습구간 관리한계 | 어떤 변수의 이탈이 위험과 연결되는가 | 토크·동력은 희소 고위험, 온도차는 드리프트 | 경보와 고장을 구분하고 특성후보 선별 |
| 5. 특성집합 비교 | A, B, C | SPC 플래그가 추가정보를 주는가 | C의 PR-AUC 개선 없음 | 최종 모델은 연속특성 중심, SQC는 진단 역할 유지 |
| 6. 모델 비교 | LR, RF, GB | 희귀고장을 가장 잘 순위화하는가 | 비선형 모델 우세 | GB를 최종후보로 선택 |
| 7. 임계값 선택 | 검증 예측점수 | 누락과 오경보의 균형은 어디인가 | 0.65 선택 | 테스트 전에 운영규칙 고정 |
| 8. 보류 테스트 | 미사용 마지막 1,500건 | 선택한 체계가 미래구간에서도 작동하는가 | 21/29 고장 탐지 | 고장유형별 약점과 적용범위 확인 |
| 9. 제약 최적화 | GB 위험점수·동력제약 | 생산성을 지키며 위험을 낮출 후보는 무엇인가 | 조건부 운전후보 도출 | 예측을 실행 가능한 탐색문제로 전환 |

## 연구의 논리적 핵심

### 경보 ≠ 고장

관리도는 기준선과 다른 상태를 찾는다. 고장 라벨은 실제 결과를 기록한다. 둘을 같은 것으로 취급하면 공정조건 변화가 전부 고장경보로 오해될 수 있다. 온도차 사례가 이를 보여준다.

### 예측확률 ≠ 운영결정

모델점수만 낮추면 생산성을 희생하는 해가 선택될 수 있다. 그래서 기계동력 하한을 제약으로 두었다. 위험과 생산성의 충돌을 명시해야 비로소 의사결정 문제가 된다.

### 최적점 ≠ 인과적 처방

관측자료로 학습한 모델을 최적화하면 데이터의 상관구조와 모델의 분할경계를 따라간다. 결과는 실험 또는 현장검증을 위한 후보이지, 물리적으로 보장된 최적점이 아니다.

## 두 종류의 최적화가 왜 분리되어 있나

논문에는 서로 다른 목적의 최적화 예제가 있다.

1. **비선형 격자탐색:** RPM과 토크에 따른 예측위험을 최소화하되 기계동력을 제약한다. ML 결과를 운전후보로 바꾸는 본 연구의 핵심 연결이다.
2. **선형계획·심플렉스 예제:** 8시간 자원 아래 두 운전모드의 배분을 설명한다. 운영연구의 자원배분 사고를 보여주는 보조 예제이며, 앞의 격자탐색과 같은 문제가 아니다.

이 둘을 하나의 최적화 결과처럼 섞지 않는 것이 중요하다.
